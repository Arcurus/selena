# Selena v2 — Tracking, Statistics, Transparency, Web UI

> **Audience:** operator reference. What Selena v2 tracks,
> how it surfaces the data, and what the web UI is the
> canonical view of. **NOT** loaded in the LLM prompt — for
> runtime context, the LLM uses the web UI directly.
>
> This is the operator-facing "what is Selena v2 for"
> doc. The internal architecture (memory hierarchy, context
> loop, the 5 layers of memory) lives in
> `selena-v2-architecture.md` — this doc is the *surface*,
> not the *internals*.

## Identity (per Arcurus 2026-06-08)

**Selena v2 is for now mainly focused on adding tracking
and statistics, and providing transparency inside and
outside in the form of a web interface.**

That's the one-line identity. The rest of this doc
explains what that means in practice.

## The 4 main subsystems

| Subsystem | What it tracks | How it surfaces | Doc |
|---|---|---|---|
| **Tracking** | Every LLM call (tokens, cost, runtime, model, provider, project) | `/api/cost-tracker`, `#cost-tracker` daily post, web UI cost panel | `docs/llm-call-tracking.md` + `docs/cost-tracking.md` |
| **Statistics** | Per-agent metrics, per-project metrics, per-entity metrics (open-world), per-day/per-5h rollups | `/api/openclaw-usage/breakdown`, `data/agent-selection-metrics-*.md`, web UI stats panel | `data/agent-selection-metrics-2026-06-05.md` (snapshot) + web UI |
| **Transparency (internal)** | The service health, the budget state, the autonomy policy's "waiting for your input" queue | `service_manager.py status`, `orchestrator-status /status`, web UI top-bar | `docs/services.md` + `selena-project-2/docs/orchestrator-api.md` |
| **Transparency (external)** | The public-facing #cost-tracker posts, the #openworld entity activity, the #selena-project work reports | Discord channels | `memory/channels-history.md` (channel table) |

## The web UI — the canonical transparency surface

The web UI is at `selena-project/web/index.html`, served at
`http://selenaastra.com:8765/` (or `http://127.0.0.1:8765/`
locally). It is the **single place** an operator (Arcurus) goes
to see:

- **Cost panel** — today's cost, 5h used % (with the budget
  bar), per-provider breakdown, per-model breakdown,
  cumulative totals
- **Stats panel** — per-project stats, per-entity stats
  (open-world), per-agent stats (lunar), disagreements,
  quarantined, active priority, orchestrator health
- **Todo panel** — the full todo list with filter by
  status / project / priority
- **LLM call panel** — recent LLM calls with token counts,
  cost, model, project
- **Pending feedback** — items where the autonomy policy
  decided `feedback_needed = true` (i.e., waiting on Arcurus)

The web UI fetches from the selena-project API server (port
8765). It does NOT talk to the orchestrator-status service
(port 8766) directly — it goes through selena-project for
uniform auth + uniform data shape.

## Tracking — what gets recorded

Every LLM call, every action cycle, every worker run is
recorded to `data/openclaw_usage.jsonl` (sliding-window
JSONL) and aggregated into the legacy `data/llm_calls.json`
cumulative counter. The fields and rollups are detailed in
`docs/llm-call-tracking.md`; the per-model pricing math is
in `docs/cost-tracking.md`.

The **what is tracked** is the source-of-truth per-call
record:
- `ts`, `sessionId`, `kind`, `channel`, `cronJobId`,
  `agentId`, `model`, `provider`
- `startedAt`, `updatedAt`, `runtimeMs`
- `tokensIn`, `tokensOut`, `cacheRead`, `cacheWrite`
- `turnCount`, `estCostUsd`

Plus the rollup levels: per-call (forensic) / per-session /
per-project / per-provider / per-model / 5h sliding window /
daily / cumulative.

## Statistics — what gets aggregated

Three rollup levels exposed to consumers:

1. **Real-time** — `data/openclaw_usage.jsonl` (live JSONL
   stream), 5h window computable in <1s
2. **Per-day** — `data/agent-selection-metrics-2026-06-05.md`
   (and similar dated snapshots), generated by the
   `agent-selection-metrics` cron
3. **Per-week / per-month** — derived from the daily
   snapshots + the legacy `data/llm_calls.json` counter

The lunar side exposes the 5h used % at
`/api/openclaw-usage/status` so the `banker` agent and
`budget-gate.service` can enforce the budget in real time.

## Transparency — the dual surface

**Internal** (operator-facing, requires auth):
- The web UI at `:8765` (HTML)
- The selena-project API at `:8765` (JSON, Bearer token)
- The orchestrator-status API at `:8766` (JSON, no auth,
  read-only)

**External** (public, no auth):
- The #cost-tracker Discord channel — daily cost report
  (auto-posted at 23:55 Europe/Berlin)
- The #openworld Discord channel — entity activity
  (auto-posted by the open-world-selena scheduler)
- The #selena-project Discord channel — work reports
  (posted by the workers)

The "transparency" identity is: **what happens in the system
should be visible to the operator (Arcurus) and to outside
observers (the Discord channels), with no manual reporting
required.** The web UI is the operator's window; Discord is
the public's window.
